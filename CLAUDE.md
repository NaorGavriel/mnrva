# CLAUDE.md

## Project

RAG system for querying a code repository in natural language. Three
components: ingestion/indexing pipeline, a LangGraph query agent, and a
refresh/sync pipeline. Full design: `@docs/architecture.md` — read it
before making structural changes; don't relitigate decisions already made
there.

## Build order

1. Ingestion & Indexing Pipeline
2. Query Agent (can stub the hybrid-search tool while (1) is unfinished)
3. Refresh & Sync Pipeline (reuses (1)'s functions per changed file)

## Stack

- Python
- LangChain — agent/tool orchestration
- tree-sitter — AST-aware chunking, one grammar per language
- Qdrant — single store for vectors, BM25 sparse vectors, and payload
  metadata.

## Decisions to honor, not re-derive

- Chunk IDs: `uuid5(file_path + symbol_name)`. Qdrant point IDs must be
  UUID.
- Hybrid search = Qdrant's native `prefetch` + `FusionQuery(fusion=RRF)`.
  Do not hand-write fusion logic.
- Sparse (BM25) vectors are generated by Qdrant at upsert time. Do not
  hand-roll a BM25/sparse embedding function.
- No import graph in MVP. Cross-file context comes from the agent's own
  tool loop (read file → notice import → read that file), not a
  precomputed graph.
- Non-code files (`.md`, `.txt`, config) are chunked via prose/semantic
  splitting, never tree-sitter.
- `db.init_client()` takes either `path=` (local dev) or `url=`
  (CI/production, e.g. Qdrant Cloud) — same function, don't branch this
  logic elsewhere.
- File discovery: `git ls-files`, filtered by an extension allowlist (not
  a blocklist) plus a small filename denylist for lockfiles.

## Module layout (Component 1)

`models.py`, `languages.py`, `repository_clone.py`, `repository_parser.py`,
`tree_parser.py`, `prose_parser.py`, `context_enricher.py`, `embeddings.py`,
`db.py`, `repository_ingester.py`

`Chunk` (in `models.py`) is the one data contract shared across all of
these — don't introduce a parallel shape.

## Conventions

- Type hints on all function signatures.
- One concern per module: LLM enrichment calls, embedding calls, and db
  writes stay in their own files.
- Adding a language = add one entry to `languages.py`'s `LANGUAGE_CONFIG`.
  Never scatter extension checks into other modules.
